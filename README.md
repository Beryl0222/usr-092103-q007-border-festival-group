# 边境节庆团组协同

面向中俄合唱交流、体育大会、口岸贸易活动的团组协同系统：境内外领队各自维护成员，
调度员当晚排定车辆、房间、演出席位与口岸批次。系统以**事件溯源 + 版本化事件交换**为核心，
覆盖并发不超售、候补转正、跨境资格有权来源、限流分批、按实际到访结算与可追溯导出。

## 业务能力

- **成员协同**：中/俄方领队分别维护本方成员（资格信息、语言需求、餐饮、保险、紧急联系人）；
  同名成员消歧留痕；成员退出记录原因与时点并联动释放资源，过程不删除。
- **跨境资格**：只接受口岸（port_authority）/领馆（consular_authority）确认；
  证件号码不进事件，仅存 `document_ref` 句柄；拒绝只留原因码。
- **容量预订**：车辆/房间/席位建模为资源，占位生命周期挂在资源聚合流上，
  以流版本做乐观并发控制，**并发预订绝不超售**；容量不足自动候补，释放后按序自动转正。
- **共用预订**：旅行社一间房/一辆车可挂接多人，挂接/移除/取消全部留痕，超容量拒绝。
- **口岸限流**：临时调减时段容量后，按团队关系树成块分批、顺延后续时段，
  不拆散小队、不删除行程；方案确认时二次复核容量。
- **结算与责任**：以口岸/现场核验的实际到访为结算依据（到访人数 × 合同单价）；
  取消费按成员变更时点适用**当时已生效的合同版本**与阶梯条款。
- **双语与导出**：中/俄双语领队清单（仅本方成员）；调度员整体风险面板；
  每次导出登记接收方、用途、字段、条数与失效时间，可吊销、可回验；按用途字段最小化。

## 资料结构

- `contracts/domain.schema.json`：领域事件公共信封与稳定枚举。
- `docs/event-catalog.md`：事件目录、payload 约定、来源授权与字段最小化矩阵。
- `src/validator.js`：公共信封与枚举校验。
- `src/domain/`
  - `catalog.js` 事件载荷契约（必填/枚举）
  - `store.js` 事件存储（聚合流版本 CAS、原子批次、JSONL 持久化）
  - `projection.js` 读模型投影
  - `policy.js` 有权来源、字段最小化、取消责任判定
  - `commands.js` 业务命令（并发重试、候补、共用预订、分批、结算）
  - `views.js` 双语清单与风险面板
  - `exports.js` 导出台账（签发/吊销/回验）
  - `demo.js` 三类活动的端到端联调剧本
- `tests/`：信封契约与 18 项领域行为测试。

## 本地检查

```bash
npm test          # 契约 + 领域行为测试（19 项）
node src/demo.js  # 端到端剧本，产物写入 out/
```

`out/` 包含：领队中俄双语清单、酒店/口岸外发名单（可核对最小化效果）、
调度员风险面板、全量事件日志 `event_log.jsonl`。

## 事件交换约定要点

1. 事件按聚合流版本号交换；消费方按 `(aggregate_id, version)` 去重与保序。
2. 同一业务过程用 `correlation_id` 串联（如一次退出联动释放、一次分批调度、一次结算）。
3. 处理跨境资格/到访事件前校验 `source.kind`；无来源或来源不匹配必须拒绝。
4. 外发数据一律走导出台账并按用途最小化；合作方不需要的证件、保险、联系人细节不得包含。
5. 事件只追加、不覆盖、不删除；修正通过新事件表达（如旧分批方案置为 superseded）。
